Mock Exam 8 · Question 2 Application

The HR_ROOT application container must support the execution of a query on a table shared by application local PDBs PDB1 and PDB2, and remote PDB PDB3. Which three are true? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
The HR_ROOT replica must exist in the remote CDB. (HR_ROOT 複本必須存在於遠端 CDB 中。)
遠端需要什麼 (Replica)： PDB3 雖然在遠端的 CDB，但它依然屬於 HR_ROOT 這個應用程式的一份子。為了讓遠端 CDB 知道如何管理這個應用程式的共通物件與元資料，您必須在遠端 CDB 建立一個 HR_ROOT 的「複本 (Replica)」。

Mock Exam 9 · Question 16 Application

Which three are true about upgrading an application in an application container? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
新題型
自動建立 Clone 確保服務不中斷： 當您在 Application Root 執行 ALTER PLUGGABLE DATABASE APPLICATION <名稱> BEGIN UPGRADE ... 時，Oracle 為了不影響底下正在運作的 Application PDBs，會在背景自動建立一個隱藏的 Application Root Clone。這個 Clone 保存了升級前的舊版本結構與資料。
明確的語法要求： 在執行升級指令時，語法強制要求您必須指名道姓：要升級「哪一個應用程式 (Name)」，以及要升級到「哪一個新版本 (Version)」，例如 ... BEGIN UPGRADE '1.0' TO '2.0'。
PDB 的延遲同步特性： 當 Application Root 完成升級後，底下的 PDB 不會跟著自動升級。它們會自動指向剛才建立的那個 Clone (也就是維持在升級前的 existing 狀態繼續運作)。直到 DBA 準備好，手動連線進各個 PDB 執行 SYNC 指令時，PDB 才會真正套用新版本的變更。
錯誤選項陷阱分析 (為什麼其他不能選)：
...PDBs are automatically synchronized with the application root clone.
錯誤原因： 這是一個文字陷阱。PDBs 是「繼續指向/依附」於那個 Clone 運作，而不是發生了「自動同步 (automatically synchronized)」的動作。在多租戶架構的術語中，「同步 (Sync)」通常意指主動去拉取並套用新的變更。
The upgrade can be performed when connected either to CDB
ROOTortoPDBSEED.
The upgrade must be performed when connected to CDB$ROOT.
錯誤原因： 連線的上下文 (Context) 完全錯誤。應用程式是安裝在特定的 Application Root 裡面（例如名為 APP_ROOT 的容器），因此升級操作必須連線到該 Application Root 內部執行，絕對不能在全域的 CDB$ROOT 或範本 PDB$SEED 中執行。

Mock Exam 11 · Question 30 Application

The HR_ROOT application container must support the execution of a query on a table shared by application local PDBs PDB1 and PDB2, and remote PDB PDB3.
Which three are true? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
把 HR_ROOT 想像成一家企業的「人資總部」，而各個 PDB 就是底下的「分店」。

本機端 (Local CDB)： 就像是台北總公司大樓。裡面有「人資總部 (HR_ROOT)」，以及它直轄的一號分店 (PDB1) 與二號分店 (PDB2)。

遠端端 (Remote CDB)： 就像是高雄分公司大樓。我們想在那邊開一家隸屬於人資部門的三號分店 (PDB3)。

為什麼高雄大樓必須要有 HR_ROOT Replica (總部複本)？

分店不能沒有直屬上司： 高雄的三號分店 (PDB3) 不能孤零零地隨便塞在大樓裡，它必須要有上級單位。所以，台北總部必須在高雄先設立一個「人資總部駐高雄辦事處」（這就是 HR_ROOT Replica）。有了辦事處，三號分店才能掛牌營業。

規章制度要自動同步： 台北總公司如果修改了員工守則或共用表單（共用資料表與結構），總部會自動把新規定派發給「駐高雄辦事處 (Replica)」。這樣一來，高雄的三號分店就能直接從辦事處拿到最新規定，不用大老遠連線回台北要資料。

總部要查帳 (跨庫查詢的對口)： 當台北總部想要查高雄三號分店的資料時，台北會派一個「代理專員」(Proxy PDB) 打電話 (Database Link) 到高雄。這通電話必須要有「駐高雄辦事處 (Replica)」來接聽並解析指令，才能指揮底下的三號分店交出資料。

遠端的資料庫不能只放一個小分店 (PDB3)，必須連同「帶隊的主管機構」(HR_ROOT Replica) 一起建置過去，這樣分店才有規矩可循，總部也才有對口可以溝通。
