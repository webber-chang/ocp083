Mock Exam 2 · Question 15 Application

HR_ROOT is an application container with the HR_APP application installed.
No application PDBs and no application seed have yet been created in HR_ROOT.
An application PDB, PDB1, must be created so that the HR_APP application?s common objects are accessible to it.
Which two methods can be used? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
在 Oracle 12c R2 之後，引入了應用程式容器 (Application Container) 的概念。這是一個專門為特定應用程式（如本題的 HR_APP）設計的微型多租戶環境。

核心架構概念：

Application Root (應用程式根目錄，如 HR_ROOT)： 應用程式的通用物件（Common Objects，如共用的資料表結構、預存程序）安裝在這裡。

Application PDB (應用程式 PDB，如 PDB1)： 實際存放各個租戶/客戶專屬資料的資料庫。它必須連接到 Application Root 才能看到共用的應用程式結構。

Application Seed (應用程式種子)： 這是一個選用的「範本」。如果建立並更新了這個種子，未來建立新的 Application PDB 時速度會非常快，因為可以直接從這個種子複製。

Synchronization (同步)： 當 Application Root 中的應用程式有安裝或升級時，底下的 PDB（或 Seed）必須執行同步指令（ALTER PLUGGABLE DATABASE APPLICATION ... SYNC），才能獲取最新的通用物件。

正確選項解析（建立並讓 PDB 取得應用程式物件的兩種合法途徑）：

D. Create the PBD1 application PDB and synchronize it with HR_ROOT. (直接建立 PDB1 並與 HR_ROOT 同步)
正確（直接法）。 您可以直接在 HR_ROOT 底下建立一個新的 Application PDB (PDB1)。建立完成後，由於它剛誕生，還不知道 HR_APP 的存在，因此您必須手動對 PDB1 執行同步作業，讓它從 HR_ROOT 擷取 HR_APP 的通用物件。

C. Create an application seed, synchronize it with HR_ROOT, and then create the PDB1 application PDB. (建立應用程式種子，將其與 HR_ROOT 同步，然後建立 PDB1)
正確（範本法）。 這是適合大規模部署的做法。您先建立一個 Application Seed，將其與 HR_ROOT 同步（讓種子內包含 HR_APP 的物件）。接著，當您建立 PDB1 時，Oracle 會自動從這個已經同步好的種子進行複製。因此 PDB1 建立好就自帶應用程式物件，不需要再對 PDB1 額外做同步。

錯誤選項解析：

A. (建立應用程式種子，並在其中安裝 HR_APP)
錯誤。 應用程式（HR_APP）必須且已經安裝在 Application Root (HR_ROOT) 中。您不能也不需要在 Seed 裡面「安裝」應用程式，Seed 只能透過「同步」來取得 Root 的結構。

B. (建立 PDB1 並在其中安裝 HR_APP)
錯誤。 與 A 的理由相同。Application PDB 只是用來放租戶的私有資料，應用程式的主體架構是統一安裝在 Root 層級的，PDB 只能透過同步來存取。如果在 PDB 內安裝，它就變成該 PDB 專屬的本地應用程式，失去了 Application Container 共用管理的意義。

E. (建立 PDB1 並與 PDB$SEED 同步)
錯誤。 PDB$SEED 是整個 CDB（容器資料庫）最底層的標準全域範本。如果要獲取特定應用程式 (HR_APP) 的變更，必須與該應用程式的專屬根目錄 (HR_ROOT) 同步，與全域的 PDB$SEED 同步是無效且不合邏輯的。

原因： Oracle 的共同物件主要分為兩類。第一類是 Oracle 內建提供的共同物件（例如系統資料表 OBJ$ 或資料字典視圖 DBA_OBJECTS），這些物件存在於根容器 (CDB$ROOT) 中，並分享給所有的 PDB。第二類是 使用者自訂的應用程式共同物件，這些物件存在於應用程式容器的根目錄 (Application Root) 中，並分享給該應用程式的 PDB。因此，共同物件確實可以存在於這兩個層級的 Root 當中。

They can be created only in an application root. (它們只能在應用程式根目錄中建立)

原因： 這裡指的是「使用者自訂 (User-defined)」的共同物件。為了保護 CDB$ROOT 的系統完整性並避免干擾整個資料庫，Oracle 不允許一般使用者直接在 CDB$ROOT 建立自訂的共同物件。如果您希望建立自己的共同物件供多個 PDB 使用，您必須建立一個 Application Container，並且只能在 Application Root 中（透過 ALTER PLUGGABLE DATABASE APPLICATION ... BEGIN INSTALL 語法）來建立這些自訂的共同物件。

為什麼其他選項是錯的？

They can exist in user-defined schemas only in application containers. (錯，CDB$ROOT 內的系統 schema 如 SYS 也有共同物件)

They can be only metadata-linked in an application container. (錯，在 Application Container 中，共同物件可以是 metadata-linked、data-linked 或 extended data-linked。)

They can be created only in CDB$ROOT. (錯，如上所述，使用者無法在 CDB$ROOT 建立共同物件，只能在 Application Root 建立。)

They can be extended data-linked in CDB$ROOT. (錯，使用者不能在 CDB$ROOT 建立任何 data-linked 或 extended data-linked 的物件。)

Mock Exam 6 · Question 40 Application

The HR_ROOT application container must support the execution of a query on a table shared by application local PDBs PDB1 and PDB2, and remote PDB PDB3. Which three are true? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
The HR_ROOT replica must exist in the remote CDB. (HR_ROOT 的複本必須存在於遠端 CDB 中)
既然遠端的 PDB3 要能讀懂 HR_ROOT 這個應用程式的共用結構 (例如共用資料表或視圖)，遠端的 CDB 裡就不能只有 PDB3，它必須擁有一個 HR_ROOT 的應用程式根目錄複本 (Application Root Replica)。有了這個複本，PDB3 才能正確同步應用程式的 Metadata。
