Mock Exam 1 · Question 36 資料庫複製與搬移

You must transport the UNIVERSITY tablespace from one database to another.
The UNIVERSITY tablespace is currently open read/write.
The source and destination platforms have different endian formats.
Examine this list of actions:
1. Make the UNIVERSITY tablespace read-only on the source system.
2. Export the UNIVERSITY tablespace metadata using EXPDP.
3. Convert the UNIVERSITY tablespace data files to the destination platform format using RMAN on the source system.
4. Copy the UNIVERSITY tablespace data files to the destination system.
5. Copy the Data Pump dump set to the destination system.
6. Convert the UNIVERSITY tablespace data files to the destination platform format using RMAN on the destination system.
7. Import the UNIVERSITY tablespace metadata using IMPDP.
8. Make the UNIVERSITY tablespace read/write on the destination system.
Which is the minimum number of actions required, in the correct order, to transport the UNIVERSITY tablespace?

📘 官方解析與重點參考
📝 重點筆記參考：
這題考的是 Oracle 跨平台傳輸表空間（Transportable Tablespace, TTS），而且題目特別設下陷阱：兩邊作業系統的「字節序（Endian format）不同」。

為你總結必記的 4 大核心觀念與標準流程：

1. 鎖定資料（起手式必備）
動作： 必須先將來源表空間設為 READ ONLY。

考點： 沒有這一步，就無法保證搬移時資料的一致性。（選項 E 直接淘汰，因為它跳過了這步）。

2. 分工合作 (Metadata vs. 實體檔案)
搬移表空間要處理兩條線：

Metadata（中繼資料）： 用 EXPDP 匯出成 Dump 檔，搬到新機器後用 IMPDP 匯入。

實體檔案（Datafiles）： 因為兩邊平台的 Endian 格式不同（例如大端序轉小端序），必須使用 RMAN (CONVERT TABLESPACE) 進行格式轉換，否則新系統會讀成亂碼。（選項 A 淘汰，因為它完全沒做轉換）。

3. 轉換只需做「一次」，檔案都要「一起搬」
考點 1： RMAN 轉換可以在來源端做，也可以在目的端做，但只需要做一次！（選項 D 淘汰，因為它在兩邊各做了一次轉換）。

考點 2： 轉換好的「Datafile」跟 EXPDP 匯出的「Dump 檔」，這兩個東西都要複製過去目的端。（選項 B 淘汰，因為它忘記把 Dump 檔複製過去）。

4. 上線啟用（收尾）
動作： 在目的端用 IMPDP 掛載成功後，將表空間改回 READ WRITE，大功告成。

Mock Exam 2 · Question 30 資料庫複製與搬移

Which four are true about a Recovery Manager (RMAN) duplication without a TARGET connection? (Choose three correct options.)

📘 官方解析與重點參考
📝 重點筆記參考：
這題（Question 30）的核心在考驗 「在沒有連接來源資料庫（Without a TARGET connection）的情況下，RMAN 複製（Duplicate）的運作規則」。

為您將這題的正確觀念與易錯陷阱統整如下：

核心觀念：沒有 TARGET 連線代表什麼？
RMAN 無法連線到「活著的」來源資料庫，所以無法直接詢問來源端的架構或即時傳送資料。它必須完全依賴存放在磁碟上的備份檔案來憑空建立出一個新的輔助例項（Auxiliary Instance）。

✅ 正確選項解析 (A, B, F)：

[選項 F] 備份來源限制： 因為沒有來源資料庫可以連線，輔助例項（新資料庫）必須直接讀取、使用指定的 磁碟備份（RMAN disk-based backups），例如 Backup sets 或 Image copies 來進行複製。

[選項 B] 必須指定 UNDO TABLESPACE： 由於無法向來源資料庫查詢 Undo 表格空間的設定（metadata），因此在下達 DUPLICATE 指令時，強制規定必須手動加上 UNDO TABLESPACE 子句，告訴新資料庫要建立什麼名稱的 Undo。

[選項 A] NOARCHIVELOG 模式必須加上 NOREDO： 如果你使用的這個備份，當初是在 NOARCHIVELOG 模式下拍的，代表沒有歸檔日誌（Archivelog）可以做復原。因此複製時必須加上 NOREDO 子句，告訴 RMAN 不要嘗試套用 Redo。

❌ 錯誤選項陷阱 (C, D, E)：

[選項 C] 網路傳輸是 Pull 而不是 Push（你的提問點）： 題目敘述 RMAN 會把備份「Push（推）」過去是錯的。因為沒有連接來源端，實際上是由新的輔助例項自己去指定的路徑把備份給「Pull（拉）」過來。

[選項 D & E] Recovery Catalog 狀態混淆： 這兩個選項把「沒有連接 Recovery Catalog」和「Target 開啟/關閉狀態」與 UNDO TABLESPACE 綁在一起，這是錯誤的觀念拼湊。需要 UNDO TABLESPACE 的唯一原因是沒有 TARGET 連線，跟 Catalog 或 Target 的狀態無關。

Mock Exam 2 · Question 51 資料庫複製與搬移

Which three are true in Oracle 19c and later releases? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
表空間狀態具備高度彈性 (對應選項 B 與 C)
Data Pump 匯入表空間後，該表空間的最終狀態可以是「讀寫 (Read/Write)」，也可以是「唯讀 (Read-Only)」。

實務盲點釐清：Data Pump 預設會將其自動轉為「讀寫」；若要讓它最終「保持在唯讀狀態」，實務上通常是 DBA 在匯入後手動補上 ALTER TABLESPACE ... READ ONLY 指令來達成。考題文字 ("can leave") 只是在強調系統允許並支援這種最終狀態。

PDB 層級的資源控管 (對應選項 D)
為了防止單一 PDB 耗盡整個容器資料庫 (CDB) 的資源，Oracle 允許在 PDB 層級設定參數（MAX_DATAPUMP_JOBS_PER_PDB），來精準限制該 PDB 可以同時執行的 Data Pump 作業數量。

PDB 狀態與表空間狀態不可混淆 (延伸觀念)
即便您希望匯入的「表空間」最終是唯讀的，在執行匯入動作的當下，接收它的 PDB 必須處於可讀寫 (Read/Write) 狀態，因為系統需要寫入 Metadata (資料字典) 才能完成掛載。不能直接將表空間匯入到一個處於唯讀狀態的 PDB 中
