Mock Exam 7 · Question 39 安裝、升級與修補

Examine this command: $ rhpctl move database sourcehome Oracle_home_path destinationhome Oracle_home_path For which two purposes can you use this command? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
Newer Release (跨大版本升級)： 例如從 Oracle 12c、18c 升級到 19c。這類操作會變更資料庫核心資料字典 (Data Dictionary) 的實體結構，因此必須使用 rhpctl upgrade database 指令
Patched Home (同版本修補/Release Update)： 例如在 Oracle 19c 內部從 19.3 更新到 19.10。這只是替換底層的二進制執行檔 (Binaries) 以修復漏洞，核心結構並未改變，因此使用的是 rhpctl move database 指令來「移動」環境。

Mock Exam 8 · Question 15 安裝、升級與修補

Which two are true about an RPM-based Oracle Database installation? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
服務配置指令碼 (Service configuration script)：
軟體安裝完成後，RPM 會在系統中放置一個設定指令碼（通常位於 /etc/init.d/oracledb_ORCLCDB-19c configure）。DBA 只要執行這個腳本，它就會在背景自動呼叫 DBCA 並幫您建好一個預設的單機版容器資料庫 (CDB) 與 PDB。這被視為 RPM 安裝流程的標準後半段作業。

您誤選的陷阱分析：
It includes the Oracle Preinstallation RPM. (您誤選的選項)
錯誤原因： 這是一個非常容易混淆的觀念！oracle-database-preinstall-19c（用來自動配置 OS 參數、建立 oracle 使用者與群組的套件）是一個獨立的 RPM 檔案，它是安裝 Database RPM 的「先決條件 (Prerequisite)」，但它並沒有被包裝 (include) 在 Database RPM 檔案裡面。您必須先透過 yum install 獨立安裝它。

Mock Exam 11 · Question 4 安裝、升級與修補

You must migrate a non-CDB Oracle 11g Database to a CDB without first performing an upgrade to the non-CDB.
User-defined objects are stored in several tablespaces in the non-CDB.
Which three methods can you use? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
關於將未升級的 Oracle 11g non-CDB 直接遷移到 CDB 的考題，這是一個非常經典的版本限制陷阱題，您勾選的答案並不完全正確。

官方題庫的正確解答應該是：

☑ Data Pump full database export and import (Data Pump 完整資料庫匯出與匯入)

☑ Data Pump full transportable database (Data Pump 完整可傳輸資料庫)

☑ Data Pump transportable tablespaces (Data Pump 可傳輸表空間)

💡 專家技術解析
這題的「破題關鍵」在於兩個條件：「來源端是 Oracle 11g」 以及 「沒有事先將 11g 升級 (without first performing an upgrade)」。

Oracle 11g 是一個非常舊的版本，它完全不懂什麼是多租戶架構 (CDB/PDB)。所有跟 PDB 扯上關係的「原生捷徑」在 11g 身上通通不管用。因此，您只能依賴 Oracle 最傳統、跨版本相容性最強的資料搬移神器：Data Pump 家族。

正確選項分析 (為什麼 Data Pump 家族可以)：

Data Pump full database export and import (expdp/impdp)： 這是純邏輯的遷移。您可以從 11g 倒出資料，然後直接灌進 12c/19c 的 PDB 中，完全不受底層架構改變的影響。

Data Pump transportable tablespaces (TTS) 與 full transportable database： 這是物理檔案遷移結合邏輯中繼資料的方法。只要 11g 升級到 11.2.0.3 以上，Oracle 官方支援直接將 11g 的資料檔 (Datafiles) 拔下來，透過 Data Pump 匯出 Metadata，然後直接「插入 (Plug)」到 12c 以上的 PDB 中，速度極快且不需事先升級整個 11g 系統。

錯誤選項陷阱分析 (為什麼您選的其他兩個不行)：

cloning the non-CDB as a PDB (您勾選的錯誤選項)：

錯誤原因： 透過 Database Link 直接執行 CREATE PLUGGABLE DATABASE ... FROM non-CDB 這種熱複製 (Cloning) 技術，要求來源端的 non-CDB 至少必須是 Oracle 12c (12.1.0.2)。11g 不支援這種無縫接軌的 PDB 複製語法。

replication using GoldenGate (您勾選的錯誤選項)：

錯誤原因： 雖然 GoldenGate 確實可以跨版本同步資料，但在 OCP 考試的標準定義中，GoldenGate 是用來做「資料複寫 (Replication)」以達到零停機時間的輔助工具，它本身無法幫您搬移/建立資料庫的基礎字典檔與結構。標準的「資料庫遷移 (Migrate a database)」解答依然會圍繞在原生工具 Data Pump 上。

the DBMS_PDB package：

錯誤原因： DBMS_PDB.DESCRIBE 是用來產生 XML 描述檔，讓 non-CDB 可以直接拔出並插入為 PDB 的套件。但這個套件是 12c 才發明的，11g 的系統裡面根本沒有這個套件，自然無法使用。

Mock Exam 11 · Question 19 安裝、升級與修補

Examine this configuration:
1. CDB1 is an Oracle container database from an older release.
2. PDB1, PDB2, PDB3, and PDB4 are pluggable databases in CDB1.
A priority list UpgrdList has these entries:
1, pdb2
2, pdb1, pdb3
You execute this command:
$ /u01/app/oracle/product/18.1.0/db_1/rdbms/admin/dbupgrade -L UpgrdList
In which order will the upgrade occur?

📘 官方解析與重點參考
📝 重點筆記參考：
新題型喔
CDB$ROOT 永遠第一個升級。
PDB$SEED 永遠在第一批 PDB 升級時處理。
Priority 1 的 PDB 接著升級。
Priority 2 的 PDB 在 Priority 1 完成後升級。
沒有列在 Priority List 的 PDB，最後才依預設方式升級。
