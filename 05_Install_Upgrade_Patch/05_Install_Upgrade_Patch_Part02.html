Mock Exam 2 · Question 48 安裝、升級與修補

Which two are true about an Oracle gold image-based installation in Oracle 18c and later releases? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
✅ 正確選項解析
A. It can be used for both Oracle Database and Oracle Grid Infrastructure installation. (可用於安裝 Oracle Database 與 Oracle Grid Infrastructure)
正確。Oracle 不僅為 Database (關聯式資料庫軟體) 提供 Gold Image，也為 Grid Infrastructure (叢集與儲存管理軟體) 提供 Gold Image。兩者的安裝模式現在都是直接解壓到各自的 Home 目錄中執行設定。

E. It can be used to install and upgrade Oracle Database for single-instance and cluster configurations. (可用於安裝與升級單一執行個體與叢集架構的 Oracle Database)
正確。Gold Image 的設計不僅是為了全新安裝 (Install)，它也是佈署 Out-of-Place Upgrade (異地升級) 或快速套用 RU (Release Update) 補丁的標準做法，且完全支援單機版 (Single-instance) 與 RAC (Cluster) 叢集環境。

❌ 錯誤選項解析
B. It can only install and configure Oracle Database software. The database has to be created separately. (只能安裝與設定資料庫「軟體」。資料庫必須另外建立)
錯誤。雖然 Gold Image 主要包含軟體二進位檔 (Binaries)，但當您執行解壓後的 runInstaller 啟動圖形介面 (OUI) 或靜默安裝時，依然會提供「建立並設定資料庫 (Create and configure a database)」的選項，您不需要強制分開執行 DBCA 才能建庫。

C. It does not require the setup wizard. (不需要安裝精靈)
錯誤。把 zip 檔解壓縮到 $ORACLE_HOME 只是第一步。您仍然必須執行 runInstaller（開啟 setup wizard 圖形介面）或使用回應檔 (Response file) 進行靜默安裝，以便將該 Oracle Home 註冊到 Central Inventory、重新連結 (relink) 執行檔，以及設定作業系統群組權限。

D. It uses a single RPM that automatically extracts and installs the Oracle Database software. (使用單一 RPM 自動解壓並安裝 Oracle Database 軟體)
錯誤。雖然 Oracle 18c 確實引入了另一種全新的「RPM-based 安裝」功能（透過 yum/dnf 安裝單一 RPM 檔），但那與本題問的「Gold Image-based (基於黃金映像檔)」是兩種不同的安裝機制。Gold Image 是使用 .zip 壓縮檔，而非 RPM。

Mock Exam 4 · Question 6 安裝、升級與修補

Examine this command:
$ rhpctl move database -sourcehome Oracle_home_path -destinationhome Oracle_home_path
For which two purposes can you use this command? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
在 Oracle 資料庫的管理與 OCP 考試情境中，"Newer Release" (新版本升級) 與 "Patch" (修補程式更新) 是兩個完全不同的維度，它們使用的工具、影響範圍與底層邏輯都不一樣。以下為你詳細對比這兩者的核心差異：1. Newer Release (新版本 / 升級 Upgrade)定義： 指的是跨大版本的升級 (Major Upgrade)。例如將資料庫從 Oracle 12c 升級到 Oracle 19c，或是從 18c 升級到 19c。底層變化： 這是非常具破壞性與結構性的變更。資料庫的核心架構、資料字典 (Data Dictionary) 的結構、甚至系統表格都會發生重大改變。使用的指令 / 工具：如果你是手動或用圖形介面升級，通常會使用 DBUA (Database Upgrade Assistant)。如果你使用 RHP (Rapid Home Provisioning) 來管理，你必須使用 rhpctl upgrade database 指令，因為它需要觸發資料字典的升級腳本。複雜度與風險： 極高。通常需要長時間的停機 (Downtime) 以及嚴格的應用程式相容性測試。2. Patch (修補程式 / 更新 Patching)定義： 指的是在同一個大版本之內，套用錯誤修正、安全性更新 (Release Update, RU) 或小幅度優化。例如你的資料庫原本是 19.3，套用 Patch 後變成 19.14，但它依然是 Oracle 19c。底層變化： 核心架構與資料字典的結構基本上維持不變，主要是替換有 Bug 的二進位執行檔 (Binaries) 或做輕微的 SQL 修補。使用的指令 / 工具：傳統作法：使用 opatch 或 opatchauto。使用 RHP 異地修補 (Out-of-place patching)：準備好一個已經打完 Patch 的新資料夾 (Destination Home)，然後使用 rhpctl move database 指令將資料庫「平移」過去運行。 複雜度與風險： 較低。透過異地修補機制，可以將停機時間縮短到只有重新啟動資料庫的那幾分鐘，且若發生問題可以隨時 rollback (退回)。

Mock Exam 5 · Question 4 安裝、升級與修補

Which three are true about using Database Upgrade Assistant (DBUA) to upgrade a database? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
Multiple databases with the same ORACLE_HOME can be upgraded simultaneously. (您勾錯的選項)
錯誤原因： 雖然同一個舊的 Oracle Home 底下可能跑了好幾個獨立的資料庫（例如 DB1, DB2, DB3），但 單一個 DBUA 視窗/程序每次只能針對「一個」資料庫（或單一個 CDB 及其 PDB）進行升級。你不能在 DBUA 介面上打勾多個獨立的資料庫叫它「同時」升級。
