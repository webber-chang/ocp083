AI與答案不符
正確答案解析
C. It allows you to select the languages supported by the Oracle database server.（正確）

說明： 在執行 Oracle Universal Installer (OUI) 安裝資料庫軟體的過程中，會有一個步驟允許你點選「Product Languages (產品語言)」，藉此選擇資料庫伺服器所需要支援的語言套件。

E. The Oracle Preinstallation RPM can be used to configure the Oracle database installation owner, the Oracle Inventory group, and an Oracle administrative privileges group.（正確）

說明： Oracle 官方提供了 Preinstallation RPM (例如 oracle-database-preinstall-19c)。執行這個 RPM 可以 (can) 幫你自動建立 oracle 使用者、oinstall 群組以及 dba 等管理群組，同時還會幫你設定好 OS 核心參數與限制，非常方便。

F. It can be done after installing Grid Infrastructure for a Standalone Server.（正確）

說明： 這是 Oracle 官方標準的安裝順序！如果你計畫使用 ASM (自動儲存管理) 或 Oracle Restart，你必須先安裝 Grid Infrastructure (GI)，然後再安裝 Oracle Database 軟體。這樣在建立資料庫時，OUI 才能自動識別出 ASM 磁碟，並將資料庫自動註冊到 Oracle Restart 中。

❌ 為什麼其他選項是錯的？
A 錯誤： 選項說「runfixup.sh 腳本可以安裝缺少的 RPMs」。

真相： 安裝程式 (OUI 或 CVU) 產生的 runfixup.sh 腳本，主要是用來自動修復 OS 核心參數 (Kernel parameters) 或 資源限制 (Limits, 如 limits.conf)。它不會幫你觸發 yum 去下載安裝缺失的 RPM 軟體包。缺少的 RPM 必須由系統管理員手動安裝。

B 錯誤： 選項說「必須 (must) 使用 Oracle Preinstallation RPM 來設定使用者和群組」。

真相： 關鍵字錯在「must」。雖然官方強烈建議使用 Preinstallation RPM 來簡化流程，但這絕對不是強制的。DBA 完全可以手動下 Linux 指令 (groupadd, useradd, 修改 sysctl.conf) 來完成所有的前置設定。

D 錯誤： 選項說「可以在安裝單機版 Grid Infrastructure 之前進行資料庫安裝」。

真相： 根據 Oracle 官方安裝指南的明確規定，如果你打算在此伺服器上使用 Grid Infrastructure (Oracle Restart)，則 GI 的安裝與設定必須發生在安裝 Oracle Database 之前。如果在 GI 之前先裝了資料庫，後續的整合與註冊會出現問題或需要大量手動重建。

Mock Exam 4 · Question 20 ⚠️ 疑慮題

Which two are true about creating pluggable databases (PDBs) using snapshots in Oracle 19c and later releases? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
題庫疑慮:
. 當選項主詞是「A snapshot copy PDB」

對應語法： CREATE ... SNAPSHOT COPY

解題聯想： 這是指利用底層儲存設備建立的「稀疏複製 PDB」。

必備條件： 看到這個主詞，立刻聯想它強烈依賴特定的檔案系統（例如 ACFS），並且可以從獨立的 clone PDB 建立。

2. 當選項主詞是「A PDB snapshot」

對應語法： CREATE ... USING SNAPSHOT

解題聯想： 這是指 Oracle 18c 推出的「PDB 快照輪播 (Snapshot Carousel)」功能，也就是時間點的歷史存檔。

必備條件： 看到這個主詞，立刻聯想它不依賴特定的檔案系統，且它可能是稀疏複製（如果在 ACFS 上）也可能是完整拷貝（如果在一般硬碟上），所以選項中只要出現「always a full copy」或「always a sparse copy」這種絕對的字眼，通常都是錯的。
A PDB snapshot depends on a storage snapshot which can only be stored on specific file systems.，這在 Oracle 官方技術文件中是錯誤的敘述。建議您在考試時，鎖定與 Snapshot copy PDB (依賴特定檔案系統) 相關的選項，並避開對 PDB Snapshot 下「Always (總是)」或「Only (只能)」等絕對限制的選項。

Mock Exam 5 · Question 23 ⚠️ 疑慮題

Examine this configuration:
1. CDB1 is an Oracle Database 12c Release 2 container database (CDB).
2. PDB1 and PDB2 are two pluggable databases (PDBs) in CDB1.

After successfully performing all the preupgrade tasks, you execute these commands from the Oracle Database 18c environment:

What is the outcome?

📘 官方解析與重點參考
📝 重點筆記參考：
有疑慮!!!
致命的參數 -c 'PDB2'：
畫面中最後一行執行的升級腳本是 $ $ORACLE_HOME/perl/bin/perl catctl.pl -c 'PDB2'。
這裡的 -c 參數非常明確，它的意思是「請『只』針對指定的 PDB（也就是 PDB2）執行升級作業」。它根本沒有叫系統去升級 CDB$ROOT、PDB$SEED 或 PDB1。

PDB2 的實際狀態不符：
回頭看前面的 SQL 指令，DBA 只有下達 ALTER PLUGGABLE DATABASE pdb1 OPEN UPGRADE;，也就是只有 PDB1 被準備好了。被點名要升級的 PDB2，此時依然停留在預設的 MOUNTED 狀態。

實務上的真實結果：
當 catctl.pl 試圖連線到 PDB2 執行升級腳本時，會因為它沒有處於 UPGRADE 狀態而直接報錯並停止 (fails)。
