Mock Exam 1 · Question 22 Multitenant

Examine the command for creating pluggable database PDB2 in container database CDB2.

Select three options, any one of which is required for it to execute successfully. (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
當執行 CREATE PLUGGABLE DATABASE pdb2 ... 且未寫路徑時，Oracle 需要知道要把 PDB$SEED 的資料檔案複製到哪裡。
Oracle 提供了以下 3 種獨立的方式（只要滿足其中任何一種即可成功執行）：
方式一（選項 B）：SQL 子句指定
在 SQL 語句中加上 CREATE_FILE_DEST = '/u01/app/oracle/oradata/CDB1/pdb2'。單獨加這個子句即可成功。
方式二（選項 C）：參數檔設定
在資料庫初始化參數中設定 PDB_FILE_NAME_CONVERT = ('/pdbseed/', '/pdb2/')。單獨設定此參數即可成功。
方式三（選項 E）：啟用 OMF 自動管理
在資料庫設定 DB_CREATE_FILE_DEST（即開啟 OMF）。單獨開啟 OMF 即可自動生成路徑並成功建立。
❌ 為什麼 A、D、F 是錯誤答案？
A. Add FILE_NAME_CONVERT clause AND set PDB_FILE_NAME_CONVERT parameter
錯誤原因：語句寫了 FILE_NAME_CONVERT 就不需要再去設 PDB_FILE_NAME_CONVERT 參數，兩者不需要同時存在。
D. Set PDB_FILE_NAME_CONVERT parameter AND enable OMF
錯誤原因：啟用了 OMF（如選項 E）就不需要設定 PDB_FILE_NAME_CONVERT；反之亦然。題幹問的是「只需具備哪一項就能成功」，因此「強迫兩者同時設定」是錯誤的。
F. Add FILE_NAME_CONVERT clause AND enable OMF
錯誤原因：同理，只要有其中一種即可，不需要同時具備。

Mock Exam 1 · Question 39 Multitenant

Which two are true about changing the LOCAL_UNDO_ENABLED property to false in a CDB? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
這題探討的是 Oracle 多租戶架構 (Multitenant Architecture) 中，將 LOCAL_UNDO_ENABLED 屬性更改為 false（關閉 Local Undo） 所帶來的影響。

核心觀念：

預設狀態 (TRUE)： Oracle 12c R2 起，預設為 Local Undo 模式，每個 PDB 都有自己專屬獨立的 Undo 表空間。

更改為 FALSE： 系統會切換回 Shared Undo 模式 (共享模式)。在這種模式下，所有的 PDB 都不再擁有自己的 Undo 空間，而是全部共用根容器 (CDB$ROOT) 裡的 Undo 表空間。

正確答案解析
A. After the change, only a common user with the required privilege can create an undo tablespace in CDB$ROOT.（正確）

說明： 當切換為 Shared Undo 模式後，Undo 表空間的建立與管理權限完全收回到根容器 (CDB$ROOT)。因此，只有具備足夠權限的公用使用者 (Common User，例如 SYS) 才能在 CDB$ROOT 中建立 Undo 表空間。（註：題目選項中的 CDB&ROOT 應為題庫的排版筆誤，實為 CDB$ROOT）。

F. After the change, each existing PDB has to be reopened for the new undo mode to take effect.（正確）

說明： 更改 Undo 模式屬於資料庫架構層級的重大異動。執行完修改指令後，系統不會立刻對運行中的 PDB 熱套用。你必須將現有的各個 PDB 關閉並重新啟動 (reopened)，新的 Undo 模式才會正式生效。

為什麼其他選項是錯的？
B 錯誤： 選項說「所有 PDB 會自動被設定去使用預設的 Undo 表空間」。雖然它們確實會去使用 CDB$ROOT 的 Undo 空間，但如選項 F 所述，這不是「自動」瞬間發生的，而是需要重啟 PDB 才能生效。

C 錯誤： 選項說「在 CDB$ROOT 中只能存在一個 Undo 表空間」。

真相： 即使在 Shared 模式下，你在 CDB$ROOT 依然可以建立多個 Undo 表空間（例如 UNDOTBS1、UNDOTBS2），只是「同一個時間點」只能有一個處於啟用 (Active) 狀態而已。

D 錯誤： 選項說「任何有權限的使用者都可以在 PDB 中建立 Undo 表空間」。

真相： 既然已經改為 false (Shared Undo)，PDB 內部就完全禁止建立自己的 Undo 表空間了。

E 錯誤： 選項說「在更改設定之前，必須先將 PDB 中現有的 Undo 表空間刪除 (dropped)」。

真相： Oracle 沒有這項強制規定。你可以先切換模式並重啟 PDB，舊有的 Local Undo 表空間會變成閒置狀態，之後 DBA 再手動去清理刪除即可，不需要在切換「之前」強制刪除。

Mock Exam 2 · Question 38 Multitenant

Oracle Managed Files (OMF) is enabled in a CDB and this command is successfully executed:

Which three are true? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
題目執行的指令是：
CREATE PLUGGABLE DATABASE app1 AS APPLICATION CONTAINER ...

這個指令的唯一作用是建立一個應用程式容器的「根目錄（Application Root）」。它不會自動幫你建立專屬的應用程式種子（Application Seed，即 app1$seed），也不會自動建立應用程式 PDB。

✅ 正確選項詳解
C. An application root PDB is created for APP1.

正確。 這是 AS APPLICATION CONTAINER 子句的直接行為。它會建立一個名為 app1 的 Application Root PDB，作為這個應用程式容器的管理核心。

D. A default service is created for the application root APP1.

正確。 在 Oracle 系統中，每當建立任何一種 PDB（包含 Application Root）時，都會自動建立一個與該 PDB 同名的預設網路服務（Default Service），讓應用程式可以透過 Listener 連線進來。

E. Application PDBs that are subsequently created in the APP1 application container will be cloned from PDB$SEED.

正確。 這是本題最容易搞混的考點。因為上述指令沒有建立專屬的 Application Seed（app1$seed）。在缺乏專屬 Seed 的情況下，如果你隨後要在這個 app1 容器內建立新的應用程式 PDB，Oracle 預設會退而求其次，從整個 CDB 層級的標準種子庫（PDB$SEED）來進行複製（Clone）。

❌ 錯誤選項陷阱
B. An application seed PDB is created for APP1.

錯誤。 建立 Application Container 絕對不會自動生成 Application Seed。如果你需要一個專屬的 Seed，你必須由 DBA 額外下達指令手動建立（例如：CREATE PLUGGABLE DATABASE AS SEED...）。

A. Application PDBs that are subsequently created in the APP1 application container will be cloned from APP1$SEED.

錯誤。 承上題 B 的邏輯，因為這個指令根本還沒有建立 APP1$SEED，所以後續建立 PDB 時無從 clone 起，只能去抓標準的 PDB$SEED（即選項 E 的行為）。

F. APP1 can never be unplugged.

錯誤。 Application Root 在本質上也是一個 PDB，它完全支援像一般 PDB 一樣被拔出（Unplug）並重新插入（Plug）到其他的 CDB 中。
