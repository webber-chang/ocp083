Mock Exam 5 · Question 19 Multitenant

Which three are true about creating container databases (CDBs) and pluggable databases (PDBs) in Oracle 19c and later releases? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
個答案中，只有一個是正確的，另外兩個踩到了名詞與機制的陷阱！ 真正正確的三個選項是：A PDB snapshot can be a sparse copy of a source PDB. (PDB 快照可以是來源 PDB 的稀疏複本) A PDB snapshot can be a full copy of a source PDB. (PDB 快照可以是來源 PDB 的完整複本) A CDB can be duplicated using the Database Configuration Assistant (DBCA) in silent mode with no configuration required before starting the duplication. (可以使用 DBCA 靜默模式複製 CDB，在開始複製前不需進行任何手動配置) 💡 專家技術解析這題考驗的是 DBA 對 Oracle 19c 中 CDB 複製工具 (DBCA vs RMAN) 的準備工作差異，以及 快照技術名詞 (PDB Snapshot vs Snapshot Copy PDB) 的嚴格區分。錯誤選項陷阱分析 (為什麼您勾的另外兩個錯了？)：A CDB can be duplicated using Recovery Manager (RMAN) with no configuration required... (您誤踩的陷阱) 錯誤原因： 就像我們在前一題 (Q18) 討論過的，使用 RMAN 執行 DUPLICATE 之前，DBA 必須親自手動準備好一個輔助執行個體 (Auxiliary Instance)。您必須寫好 pfile、啟動到 NOMOUNT 狀態、甚至設定 SQL*Net 連線。這絕對稱不上是 "no configuration required (無需配置)"。正確做法： 相反地，如果您使用 DBCA 靜默模式 (dbca -createDuplicateDB ...)，DBCA 會在背景全自動幫您建 pfile、開輔助執行個體、跑 RMAN 複製，這才是真正的「無需事前配置」。A snapshot copy PDB can be a full copy of a source PDB. (您誤踩的陷阱) 錯誤原因： 這是 Oracle 考題最愛玩的文字遊戲。Snapshot Copy PDB： 這是一項依賴底層儲存系統 (如 ACFS 或 ZFS) 快照技術的功能。既然是儲存層級的快照指標，它天生就必定是稀疏的 (Sparse)，絕對不會是「完整複本 (Full copy)」。PDB Snapshot： 這是 18c 以後引入的獨立功能（常搭配快照輪播 Snapshot Carousel 使用）。它可以是唯讀的「完整拷貝 (Full copy)」，也可以搭配特定儲存變成「稀疏拷貝 (Sparse copy)」。所以這題的正確答案是另外兩個描述 PDB Snapshot 的選項
