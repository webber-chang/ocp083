While backing up to an SBT channel, you determine that the read phase of your compressed Recovery Manager (RMAN) incremental level 0 backup is a bottleneck.
FORCE LOGGING is enabled for the database.
Which two could improve read performance? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
D. Enable asynchronous disk I/O.（正確）

解析： 當 RMAN 從磁碟（或 ASM）讀取資料檔案時，如果能啟用非同步磁碟 I/O (Asynchronous Disk I/O)，伺服器行程可以在發出一個 I/O 請求後不必等待其完成就能繼續執行其他工作，藉此大幅提升資料讀取的並行度與吞吐量，解決讀取瓶頸。

E. Increase the level of RMAN multiplexing.（正確）

解析： 增加 RMAN 多工處理的程度（Multiplexing Level）會讓 RMAN 同時從多個資料檔案讀取區塊並寫入同一個備份片段中。這能提高 RMAN 填充緩衝區的速率，使伺服器能夠以更快的速度連續讀取資料（特別適用於防止磁帶設備因為讀取緩慢而導致串流中斷/streaming break 的情況）。

Mock Exam 1 · Question 44 RMAN

Which two are true about RMAN duplexed backup sets? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
這題考的是 RMAN (Recovery Manager) 雙重備份集 (Duplexed Backup Sets) 的運作規則與限制。

核心觀念：什麼是雙重備份集？
為了提升備份的安全性（避免單一檔案損壞），RMAN 允許你為「同一個備份集」建立多個一模一樣的副本（最多可達 4 份）。
達成的方式有兩種：

備份當下同時產生： 下 BACKUP 指令時加上 COPIES 參數。

事後拷貝： 針對已經備份好的檔案，使用 BACKUP BACKUPSET 指令再複製一份出來。這題的選項主要都是在考「事後拷貝」的路徑限制。

正確答案解析
B. A non-duplexed backup set written to disk can be duplexed to disk by backing up the backup set that is already on disk.（正確）

說明： 你可以把「已經存在硬碟 (Disk) 上」的單一備份集當作來源，透過 BACKUP BACKUPSET 指令，將它拷貝到硬碟上的另一個位置，藉此完成雙重化。

D. A non-duplexed backup set written to disk can be duplexed to tape by backing up the backup set that is already on disk.（正確）

說明： 你可以把「已經存在硬碟 (Disk) 上」的備份集當作來源，將它拷貝到「磁帶 (SBT)」上。這是實務上極度常見的 D2D2T (Disk-to-Disk-to-Tape) 策略：先快速備份到本機硬碟，離峰時間再把硬碟的備份檔轉存到磁帶做長期保存。

為什麼其他選項是錯的？
⛔ 關於來源設備的致命限制 (選項 C 與 E)
RMAN 有一個非常嚴格的限制：不能把「磁帶 (SBT)」當作 BACKUP BACKUPSET 的來源。

C 錯誤： 選項說可以把已經在磁帶上的備份集，拷貝到另一卷磁帶 (Tape to Tape)。RMAN 不支援這種操作，這通常要靠底層磁帶櫃的硬體功能來達成。

E 錯誤： 選項說可以把已經在磁帶上的備份集，拷貝回硬碟 (Tape to Disk)。RMAN 同樣不支援將磁帶上的備份集作為來源進行備份。

⛔ 關於通道 (Channel) 數量的錯誤描述 (選項 A 與 F)
如果你是在備份的「當下」同時寫入多份副本到磁帶 (SBT)，RMAN 的規則是：每一個副本都需要一個獨立的 SBT Channel。

A 錯誤： 選項說雙重備份使用的 SBT 通道數量與單一備份「相同」。這是錯的，因為你要同時寫入兩份，就需要兩個通道，數量不會相同。

F 錯誤： 選項說雙重備份「總是使用兩倍 (twice as many)」的通道。這也是錯的，因為 RMAN 允許你最高產生 4 份副本。如果你設定 COPIES 3，就會需要 3 個通道，而不總是兩倍。這個選項太過絕對。

Mock Exam 2 · Question 40 RMAN

Which three are true about Recovery Manager (RMAN) in Oracle Database 19c and later releases? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
選項 D 與 F（正確）： RMAN 復原目錄（包含 Virtual Private Catalog, VPC）在底層實體上，就只是一個存放中繼資料的資料庫 Schema。Oracle 完全支援將這個 Schema 建立在傳統的非容器資料庫（Non-CDB）中，或者建立在較新的插接式資料庫（PDB）裡。

選項 E（正確）： RMAN 允許你直接將 PDB 作為目標資料庫來連線（例如透過 TNS 連線：CONNECT TARGET sys@pdb_name），藉此對單一 PDB 執行備份或還原操作。

為什麼其他選項是錯的？
A 錯誤： 此選項說「只有在 (only possible) 使用 VPC 時才能將 PDB 作為目標連線」。這是錯的，因為你完全可以不掛載任何目錄（預設的 NOCATALOG 模式），直接依靠目標端 CDB 的控制檔來連線並管理 PDB。

B 錯誤： 此選項說「使用『任何 (any)』RMAN 目錄都可以連線到 PDB」。這是 Oracle 12c 以後常考的陷阱：如果你連線到 PDB 作為目標，且你決定要搭配目錄使用，Oracle 強制規定你只能使用 VPC，絕對不能使用基礎目錄 (Base Recovery Catalog)。

C 錯誤： 此選項說 VPC「必須 (must)」建立在 PDB 中。如同選項 F 所證實的，VPC 也可以建立在 Non-CDB 中，並沒有強制綁定在 PDB 的限制。

Mock Exam 2 · Question 45 RMAN

Which two are true about creating RMAN backups for an Oracle container database? (Choose two.)

📘 官方解析與重點參考
📝 重點筆記參考：
正確選項解析
B. The BACKUP DATABASE command will create a pluggable database (PDB) backup when RMAN is connected to a PDB.
在多租戶架構中，RMAN 的操作範圍會受到「連線對象」的限制。當您使用 RMAN 直接連線到某個特定的 PDB（例如：RMAN TARGET sys@pdb1），您對 RMAN 下達 BACKUP DATABASE; 指令時，RMAN 只會備份「目前連線的這一個 PDB」，而不會備份整個 CDB。

E. The BACKUP PLUGGABLE DATABASE command can be used to back up CDB$ROOT.
當您連線到 CDB 的根容器 (CDB$ROOT) 時，可以使用 BACKUP PLUGGABLE DATABASE 指令來備份特定的 PDB。特別的是，Oracle 在這裡將 CDB$ROOT 也視為一個特殊的 PDB，因此您可以使用 BACKUP PLUGGABLE DATABASE "CDB$ROOT"; 這樣的語法來單獨備份根容器。
❌ 錯誤選項解析
A. Tablespaces from different PDBs with identical names must be backed up by connecting RMAN separately to each PDB to back up the tablespaces.
錯誤。如果不同 PDB 中有相同名稱的 Tablespace（例如大家都叫 USERS），您不需要分別連線到每個 PDB 才能備份。您可以直接連線到 CDB$ROOT，然後使用 PDB名稱:Tablespace名稱 的格式來指定備份，例如：BACKUP TABLESPACE pdb1:users, pdb2:users;。

C. SPFILE backups can be created while connected to an application root PDB.
錯誤。伺服器參數檔 (SPFILE) 屬於整個 CDB 層級的配置檔案，PDB（包含 Application Root PDB）本身並沒有獨立的 SPFILE。因此，必須連線到 CDB$ROOT 才能備份 SPFILE，無法在 PDB 層級進行。

D. The BACKUP DATABASE PLUS ARCHIVELOG command will back up archive logs when RMAN is connected to a PDB.
錯誤。歸檔日誌 (Archive Logs) 是實體資料庫層級 (CDB-level) 的檔案，所有的 PDB 都是共用同一組 Redo Logs 與 Archive Logs。因此，當 RMAN 連線到單一 PDB 時，是沒有權限也沒有辦法使用 PLUS ARCHIVELOG 來備份歸檔日誌的。備份歸檔日誌必須在連線至 CDB$ROOT 的狀態下進行。
