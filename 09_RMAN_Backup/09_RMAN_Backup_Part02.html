Mock Exam 3 · Question 3 RMAN

Which three are true about RMAN archival backups with the RESTORE POINT clause? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
B. The SPFILE is included in the archival backup. (SPFILE 會被包含在歸檔備份中)

解釋： 為了確保這個備份在未來（可能是幾年後）能夠獨立且完整地被還原，RMAN 在建立歸檔備份（Keep Backup）時，會自動將 SPFILE（伺服器參數檔）以及控制檔（Control File）包含進去。這樣一來，即使未來的環境全毀，你依然有啟動資料庫所需的參數與架構資訊。

D. Archive logs are retained if they are necessary to allow the database to be recovered to a consistent state when an archival backup is restored. (如果為了讓歸檔備份還原時能恢復到一致狀態，必要的 Archive Logs 會被保留)

解釋： 如果你是在資料庫開啟（Online）的狀態下進行備份，資料庫在備份期間可能會有異動。為了確保這份備份還原後能達到「資料一致性」，RMAN 會自動備份並保留「備份期間產生」的 Archive Logs（歸檔日誌），這些日誌會跟著這個歸檔備份一起被長期保留。

E. The ARCHIVAL attribute for a backup overrides the RMAN retention policy. (備份的 ARCHIVAL 屬性會覆蓋 RMAN 的保留策略)

解釋： 這是歸檔備份（使用 KEEP 子句）最主要的功能。它會宣告這個備份是特殊的（例如 KEEP UNTIL TIME ... 或 KEEP FOREVER），因此 RMAN 預設的保留天數或備份份數限制（Retention Policy）對它無效，確保它不會被意外標記為廢棄（Obsolete）並刪除。

錯誤選項為何不正確：
A. All archive logs are retained... (所有的 Archive logs 都會被保留直到下次歸檔備份)

錯誤原因： RMAN 只會保留「能讓該次備份恢復到一致狀態」所必需的特定 Archive logs，而不是保留所有的日誌。

C. They are never considered obsolete by RMAN. (它們永遠不會被 RMAN 視為廢棄)

錯誤原因： 如果你設定的是 KEEP UNTIL TIME '特定日期'，當超過那個日期後，它還是會被視為廢棄（Obsolete）。只有使用 KEEP FOREVER 才會永遠不廢棄。

F. They can optionally be written to a fast recovery area (FRA). (它們可以選擇寫入快速復原區 FRA)

錯誤原因： 歸檔備份（Keep Backups）不能存放在 FRA（Fast Recovery Area）中。因為 FRA 的空間是由資料庫根據保留策略自動管理的，而歸檔備份不受保留策略控管，如果放在 FRA 會導致空間管理機制混亂，RMAN 會阻擋這種操作。

E. Compression can be done only for locally managed tablespaces. (壓縮只能對本地管理的表空間進行)
解釋： （這就是剛剛提到的經典陷阱！）這裡指的「壓縮」包含了 RMAN 預設啟用的 「未用區塊壓縮 (Unused Block Compression)」。RMAN 備份時為了加速並節省空間，會自動跳過那些「高水位線 (HWM) 以下，但目前為空」的區塊。要做到這點，RMAN 必須讀取表空間的點陣圖 (Bitmap)，而只有本地管理表空間 (LMT, Locally Managed Tablespaces) 才具備 Bitmap 架構。舊版的字典管理表空間 (DMT) 無法使用此功能。

Mock Exam 3 · Question 26 RMAN

Which three are true about using an RMAN Recovery Catalog with a pluggable database (PDB) target connection in Oracle Database 19c and later releases? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
A. The base catalog owner must give the Virtual Private Catalog access to metadata for one or more PDBs. (基礎目錄擁有者必須授予虛擬私有目錄存取一個或多個 PDB 元資料的權限)

解釋： 正確。Virtual Private Catalog (VPC) 的本質是 Base Catalog 的一個子集。為了讓 VPC 能夠管理特定的 PDB，Base Catalog 的擁有者（通常擁有整個 CDB 的權限）必須透過 GRANT 指令，明確將特定 PDB 的 metadata 存取權限授權給 VPC 的擁有者。

E. The target PDB must be registered in a Virtual Private Catalog. (目標 PDB 必須註冊在虛擬私有目錄中)

解釋： 正確。在 Oracle 架構中，Base Catalog 是用來註冊整個 CDB 的。如果您只想要連接並備份/還原單一個 PDB（PDB target connection），該 PDB 不能直接註冊在 Base Catalog 中，而是必須註冊在為該 PDB 專門建立的 Virtual Private Catalog (VPC) 中。

D. The base catalog must be used by RMAN when performing point-in-time recovery for the PDB registered in the Virtual Private Catalog. (當為註冊在虛擬私有目錄中的 PDB 執行時間點復原時，RMAN 必須使用基礎目錄)

解釋： 正確。執行 PDB 的時間點復原 (PITR) 是一個複雜的過程，RMAN 在底層會自動建立一個輔助執行個體 (Auxiliary Instance)。這個過程需要獲取整個 CDB 層級的元資料（例如 Control File 資訊、CDB 的 UNDO 資訊等），而這些資訊存在於 Base Catalog 中，因此在執行 PDB PITR 時，RMAN 仍會需要存取 Base Catalog。

錯誤選項分析：

B. The base catalog must be enabled for Virtual Private Catalog use. (基礎目錄必須先被啟用以供虛擬私有目錄使用)

解釋： 錯誤。Base Catalog 在建立後 ( CREATE CATALOG ) 就具備了支援 VPC 的能力，不需要額外執行所謂的 "enable" 指令。只要 Base Catalog 擁有者直接給予權限 (GRANT CATALOG FOR DATABASE...) 即可建立 VPC。

C. The target PDB must be registered in a base catalog. (目標 PDB 必須註冊在基礎目錄中)

解釋： 錯誤。如同選項 E 所述，Base Catalog 是用來註冊整個 CDB 的。單一 PDB 是註冊在 Virtual Private Catalog 裡，不能直接註冊在 Base Catalog。

F. The target PDB must be registered in both the base catalog and the Virtual Private Catalog. (目標 PDB 必須同時註冊在基礎目錄與虛擬私有目錄中)

解釋： 錯誤。與選項 C 的理由相同，PDB 不會直接註冊在 Base Catalog 中，只會註冊在 VPC 裡。

Mock Exam 3 · Question 31 RMAN

Which three are true about interpreting Recovery Manager (RMAN) error stacks returned to standard output? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
F. Media Management errors appear as a line with "Additional information" and a number. (媒體管理錯誤會顯示為包含 "Additional information" 及一個數字的行)

解釋： 正確。當 RMAN 透過 Media Management Layer (MML) 與第三方磁帶或備份軟體溝通並發生錯誤時，RMAN 本身通常會拋出 ORA-19511 等錯誤，並在堆疊中附帶一行 Additional information: <數字>。這個數字是第三方媒體管理廠商（如 NetBackup, Commvault）專屬的錯誤代碼，供 DBA 去查閱廠商的文件。
