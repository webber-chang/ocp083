Mock Exam 8 · Question 22 效能監控與調校

Which statements are true about SGA_MIN_SIZE? (Choose three.)

📘 官方解析與重點參考
📝 重點筆記參考：
這題考驗的是 DBA 對 Oracle 多租戶架構中 PDB 記憶體資源隔離與保障 (Resource Management) 參數的理解。SGA_MIN_SIZE 是用來確保某個關鍵的 PDB 永遠能獲得最基本的 SGA 記憶體配額。

正確選項分析：

PDB 專屬參數 (Modifiable in a PDB / No effect at CDB level)： 這個參數的設計初衷就是為了解決「多租戶間的資源競爭」。因此，您必須登入到特定的 PDB 內部去修改它，以此宣告「這個 PDB 最少需要多少記憶體」。如果您在最上層的 CDB$ROOT 設定它，Oracle 根本不知道您想保障的是哪一個 PDB，因此該設定會被直接忽略 (has no effect)。

數值範圍限制 (0 to 100%)： 當您在特定的 PDB 內設定 SGA_MIN_SIZE 時，它的語法容許範圍是 0 到整個容器資料庫 (CDB) SGA_MAX_SIZE 的 100%。(備註：雖然語法上允許設到 100%，但在實務運作上，所有 PDB 的 SGA_MIN_SIZE 總和不能超過 CDB 總 SGA 的 50%，否則會報錯，但單一參數的設定範圍確實是 0~100%)。

您誤選的陷阱分析：

It is modifiable in a CDB. (您誤選的選項)

錯誤原因： 這裡的 "in a CDB" 指的是在 CDB$ROOT 整個容器資料庫層級。雖然您可能可以用 ALTER SYSTEM 語法去下這個指令，但就如另一個正確選項所述，這樣做「毫無作用 (no effect)」。在 Oracle 認證考試的邏輯中，既然設定了沒用，就不會將其視為「可以在 CDB 中修改 (modifiable in a CDB)」的有效特性。

其他錯誤選項原因：
It can be set via ALTER DATABASE command.
錯誤原因： 記憶體配置參數（如 SGA 相關參數）必須使用 ALTER SYSTEM 指令來修改，而不是用 ALTER DATABASE。
